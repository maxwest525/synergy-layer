## 3. Module boundaries

Three filename suffixes carry the architecture. They are conventions, not
enforced by the compiler, and they are consistent across all 338 lib files.

- **`*.server.ts` (77)** — server-only. Reads `process.env`, uses
  `supabaseAdmin` (`src/integrations/supabase/client.server.ts`), or calls an
  outbound provider. Never imported by a component.
- **`*.functions.ts` (41)** — TanStack server functions. The **only** sanctioned
  door from browser to server. `attachStoredAuth`
  (`src/lib/server-function-auth.ts:68`, a `createMiddleware({ type: "function" }).client`)
  attaches the operator token; `csrfMiddleware` in `src/start.ts` filters on
  `handlerType === "serverFn"`.
- **Everything else in `src/lib`** — pure, isomorphic, unit-tested. This is where
  the rule engines and view models live.

Sub-packages under `src/lib/`: `ai/` · `authority/` · `connectors/` ·
`dataforseo/` · `execution/` · `knowledge/` · `mcp/` · `measurement/` ·
`openai-ads/` · `openseo/` · `proposals/` · `seo-runs/` · `serpapi/` · `umami/`.

`src/registry/` is the capability registry: `index.ts`, `types.ts`,
`sync.server.ts`, `operational-bridges.test.ts`, and `modules/` with one file per
provider surface — `search-console.ts`, `ga4.ts`, `dataforseo.ts`,
`serpapi-ads.ts`, `self-hosted-analytics.ts`, `automation-runtime.ts`,
`agent-integrations.ts`, `content-operations.ts`, `growth-operations.ts`,
`research-operations.ts`, `openai-ads.ts`.

`src/integrations/` holds the two platform clients: `supabase/` (`client.ts`,
`client.server.ts`, `auth-middleware.ts`, `auth-attacher.ts`, generated
`types.ts`, and `previewAuthStorage.ts` — Lovable-regenerated, deliberately
ignored by `eslint.config.js:24`) and `lovable/index.ts`.

`probeConnector` (`src/lib/connectors/probes.server.ts:298`) checks in this
order, and the order is the design:

1. `key === "google_ads"` → dynamic `import("./google-ads.server")` (line 302).
   **The escape hatch** — a connector needing more than a static request
   descriptor gets its own module.
2. readiness `missing` → `missing_configuration`, no network call.
3. `key ∈ noSafeProbe` (line 34: `google_search_console`, `google_analytics_4`,
   `pagespeed_insights`, `perplexity`) → `configured_no_safe_probe`. No call, no
   spend.
4. `configuredRequest(key, env)` → `RequestDescriptor { url, headers }` (line 29)
   → fetch, 10s timeout (line 344), `readBoundedResponseBody` capped at 32 KB.

Supporting symbols: `basic()` (line 62), `umamiProbeAuth()` (line 177) which
mirrors `umamiAuthHeaders()`'s precedence on purpose, `redactedEndpoint()` (line
185) which stores origin + pathname only, and the shape validators
`isOpenSeoHealth` / `isDataForSeoSuccessEnvelope`.

Thin wrappers: `probeVpsScraper()` (`connectors/vps-scraper.server.ts:45`) and
`probeN8n()` (`connectors/n8n.server.ts:35`), both one-line delegates.

## 10. Dead, duplicated and disconnected code

### 10.1 Registered and ignored — the highest-value category

Env-var names declared in the connector catalog or a test, with **zero**
consumers outside `catalog.ts` / `probes.server.ts` / `surface-inventory.ts`:

- **`SEARXNG_BASE_URL`, `SEARXNG_USERNAME`, `SEARXNG_PASSWORD`** — catalogued
  (`connectors/catalog.ts:202-208`), probed (`probes.server.ts:142-146`), read by
  nothing. `UNWIRED`.
- **`GOOGLE_ADS_CUSTOMER_ID`** — required (`catalog.ts:166-175`), normalized
  (`catalog.ts:241`), read by no call. `google-ads.server.ts` only calls
  `customers:listAccessibleCustomers`, which takes no customer id.
- **`N8N_API_KEY`** — appears only in `connectors/connections.server.test.ts:38,57,63`.
  Not in the catalog. A dead name in a fixture.

### 10.2 The GA4 ingredients that were never assembled

`src/lib/measurement/ga4.server.ts` exports three symbols that nothing outside
the file references:

- `DATA_ENDPOINT` (line 12)
- `ga4RunReportEndpoint(property)` (line 15) — its doc comment reads *"The exact
  Data API call AOOS makes for a property inventory read"*
- `fetchGa4Inventory` (line 253)

And `ga4ResponseProvesAuthentication` (line 55) — a helper whose only purpose is
to separate a rejected credential (401) from an authenticated-but-refused read
(403/400) — is referenced, per Serena, only by `fetchGa4Inventory` in the same
file and by `measurement.test.ts:245-248`.

These are exactly the parts a connector probe would need, exported as though for
one, with no probe consuming them. Meanwhile `google_analytics_4` sits in
`noSafeProbe`.

### 10.3 Over-exported symbols

A full scan of every `export function` / `export const` in the 224 non-test
`src/lib` files found **97 exported symbols with no reference anywhere outside
their defining file** — not even a test. The complete list is at
[`../integrations/_audit/unreferenced-exports.txt`](../integrations/_audit/unreferenced-exports.txt).

This is over-export, not necessarily dead code: many are threshold constants
(`page-checks.ts :: TITLE_MAX`, `TITLE_MIN`, `THIN_CONTENT_WORDS`,
`dataforseo/backlink-strategy.ts :: PROFILE_DEFAULTS`, `LINK_GAP_DEFAULTS`,
`VELOCITY_DEFAULTS`) exported to make them citable, which serves the "no invented
thresholds" rule in `AGENTS.md`. Others look like genuinely unreachable
functionality worth a decision:

- `src/lib/dataforseo/labs.server.ts :: discoverCompetitors`, `collectRankedKeywords`
- `src/lib/dataforseo/serp.server.ts :: liveSerp`, `postbackUrl`
- `src/lib/search-console.server.ts :: collectPageQuery`, `backfillPageQueryGaps`
- `src/lib/proposals/daily.server.ts :: runProposalJobForTenant`
- `src/lib/seo-runs/functions.ts :: createSeoRun`
- `src/lib/title-h1-proposals.functions.ts :: generateTitleH1Proposal`
- `src/lib/change-requests.functions.ts :: markChangeRequestApplied`
- `src/lib/workflow-runner.server.ts :: parseGraph`, `orderNodes`, `isManualOnlyNode`
- `src/lib/serpapi/creatives.server.ts :: rebuildCreativeFamilies`

Three of those are `*.functions.ts` exports — server functions with no caller,
which means a browser-reachable endpoint that no UI invokes. Worth checking
before the next release.

**Caveat on method:** this is a whole-word grep across `src/` and `scripts/`,
not a type-aware reachability analysis. A symbol reached only through a
re-export barrel or dynamic import would be a false positive. Treat the list as
a candidate set, not a delete list.

### 10.4 Duplication

- **Three page renderers** — Crawl4AI, self-hosted Firecrawl, cloud Firecrawl.
  Precedence is explicit in `page-audit.server.ts:460-462` and
  `firecrawl-endpoint.ts`. Intentional redundancy, not duplication.
- **Two model paths** — see §8. This one is not intentional.
- No duplicated network call was found inside a single request path.

### 10.5 What is *not* wrong

- **Zero** `TODO`, `FIXME` or `HACK` in `src/` or `scripts/` outside tests.
- **Zero** `vi.mock`, `createMock` or `__mocks__` outside test files.
- Every `placeholder` match is a React input prop or the skeleton component at
  `src/components/os/primitives.tsx:312`.

# AOOS UX Blueprint

Synthesized from five sourced research passes (Search Atlas/OTTO, Semrush, Ahrefs, Surfer/seoClarity/Conductor, GSC/Google Ads, Linear/Superhuman/GitHub, Wix/Squarespace/Yoast, Shopify/Plausible/Fathom, Intercom/HubSpot/Notion/Vercel, NN/g, W3C COGA, GOV.UK, Polaris). Unverified items are flagged inline.

---

## 1. Category-page template (exact order, top to bottom)

Every one of the 6-8 pages uses this identical skeleton. Structural budget: two disclosure levels max — level 1 is the page, level 2 is an expanded card or overlay. Nothing three clicks deep (NN/g progressive disclosure: designs beyond 2 levels "typically have low usability because users often get lost" — https://www.nngroup.com/articles/progressive-disclosure/).

**Section 1 — Plain-words header (title + one-sentence purpose + status light)**
- Title in the owner's goal words, not tool names: "Get found on Google," not "GSC." Semrush's own 2024 redesign moved from tool-name nav to objective-named toolkits because the old nav caused "cognitive overload" (https://www.semrush.com/news/260365-new-semrush-navigation/ ; https://internet.agency/en/semrush-unveils-major-redesign-a-deep-dive-into-the-new/).
- One sentence under the title saying what the page is for: "This page shows how people find you on Google." W3C COGA pattern "Make the purpose of your page clear" (https://www.w3.org/TR/coga-usable/design_guide.html). Search Atlas keeps this framing only in marketing, not in-product — reviewers still call it "not for a complete beginner" (websites2know.com via researcher 1) — putting it in the header is where AOOS beats the benchmark.
- One green/yellow/red status with a one-sentence verdict: "Search: OK — clicks steady, 2 things worth fixing." Yoast traffic-light model; Yoast explicitly says a mix of colors is acceptable, which prevents completionist anxiety (https://yoast.com/yoast-seo-traffic-lights/).

**Section 2 — Metric row (3-5 cards, no more)**
- Each card: plain-verb name ("People who clicked through to your site," not "CTR"), the number, delta vs last period in green/red, tiny trend. Number + delta answers the returning owner's only question: better or worse? (Ahrefs Dashboard — https://ahrefs.com/academy/how-to-use-ahrefs/dashboard/overview ; Shopify overview cards — https://help.shopify.com/en/manual/reports-and-analytics/shopify-reports/overview-dashboard/using-the-overview-dashboard).
- The whole card is the drill-down link; flagged cards get a "See why" link (Shopify, same source). Keep the technical name (CTR, impressions) in small text/tooltip for cross-reference with GSC itself (researcher 5).
- One plain line under each number saying what it means — the explanation lives next to the number, never in a help center (Wave's documented weakness — https://support.waveapps.com/hc/en-us/articles/360041575251-View-and-understand-your-profit-loss-statement).

**Section 3 — Suggestion queue (above the fold, capped)**
- The queue is the page's center of gravity, visible without scrolling (COGA "Make it easy to find the most important actions" — https://www.w3.org/TR/coga-usable/design_guide.html).
- Capped at 5-7 cards per visit, ranked by impact, arriving on a named schedule ("Monday's suggestions"), never a continuous flood. Surfer Grow Flow's finite weekly batch is the model (feature's own docs now 404 — pattern sourced from https://www.hashmeta.ai/en/blog/surfer-seo-grow-flow-explained-how-to-prioritize-seo-tasks-with-ai and https://www.robbierichards.com/seo/surfer-seo-review/); the failure it prevents is documented at Search Atlas — "dozens (sometimes hundreds) of suggestions," "3.5 hours weekly reviewing" (https://themarketingagency.ca/blog/search-atlas/).
- Sort by exactly three impact tiers with fixed colors, identical across all pages: "Fix now" (red) / "Worth doing" (yellow) / "Nice to have" (blue). Both Semrush and Ahrefs converged on exactly three (https://www.semrush.com/kb/541-site-audit-issues-report ; https://ahrefs.com/academy/how-to-use-ahrefs/site-audit/introduction).
- Tabs on the queue: Open / Ignored / Done. Ignored has one-click restore (Semrush Hidden tab + "Restore from hidden" — https://www.semrush.com/kb/541-site-audit-issues-report). Done is a permanent, inspectable receipt pile (Wix SEO Assistant's Completed Tasks — https://support.wix.com/en/article/optimizing-your-site-with-the-wix-seo-assistant).
- Empty state is positive: "Nothing needs you right now on Search," with the date cleared. GSC only shows recommendation cards when there's "something interesting and actionable" — nothing shown means you're fine (https://support.google.com/webmasters/answer/15107108?hl=en).

**Section 4 — Detail links (truncated lists, overlay expansion)**
- Every list (top queries, top pages, issues) shows ~5-7 rows with an expand control that opens an overlay/modal — never a route change. Plausible/Fathom's single-page model is why non-experts use them where GA4 gets abandoned (https://plausible.io/docs/top-pages ; https://usefathom.com/features/vs-google-analytics).
- Disclosure labels are literal: "Show all 23 queries," never "More" or "Details" (NN/g information scent — https://www.nngroup.com/articles/progressive-disclosure/).
- No route ever lands on an unfiltered table. Card/tile clicks open the detail view with the filter pre-applied — Ahrefs Opportunities cards open reports "with filters pre-applied" (https://help.ahrefs.com/en/articles/9127446-where-can-i-quickly-find-opportunities-to-improve-my-website-s-seo).

## 2. Suggestion card anatomy

**Fields, top to bottom:**
1. **Impact chip** (Fix now / Worth doing / Nice to have) + **type badge** (Fix / Grow / Setup — GSC's Issue/Opportunity/Configuration triad, https://support.google.com/webmasters/answer/15107108?hl=en) + **state chip** (Suggested / Approved / Live — OTTO's explicit Recommended → Deployed → Live state machine, https://help.searchatlas.com/en/articles/11880172-otto-setup-functionality-and-deployment).
2. **Plain-words claim**, one decision only: "This page's title doesn't say what city you serve." If a suggestion bundles two changes, split it into two cards (GOV.UK one-thing-per-page — https://designnotes.blog.gov.uk/2015/07/03/one-thing-per-page/).
3. **Evidence line** pulled from real data: "12 clicks last month, ranking #14 for 'movers in Tulsa'" + scope: "affects 6 pages" (Semrush issue rows carry count + trend in the row — https://www.semrush.com/kb/541-site-audit-issues-report; evidence-line pattern from seoClarity — https://www.seoclarity.net/technology/actionable-insights/).
4. **Before → after preview** of what approving changes (Search Atlas before/after comparisons — https://max-productive.ai/ai-tools/search-atlas/).
5. **Three collapsed explainer lines, same template on every card in every category:** "What this is" / "Why it matters for getting moving jobs" / "What approving will do." Ahrefs uses this fixed three-heading template on every issue (https://help.ahrefs.com/en/articles/2456799-broken-redirect-error-in-site-audit); Linear attaches an expandable "why" to every AI suggestion (https://linear.app/docs/triage-intelligence). The fixed template is the accessibility feature: read one card, skim all of them.
6. **Verb footer, fixed order and position everywhere** (Polaris card-footer actions — https://polaris-react.shopify.com/patterns/card-layout):
   - **Approve** — the only filled/primary button (Polaris: more than two filled buttons "degrades hierarchy and causes confusion" — https://polaris-react.shopify.com/patterns/common-actions/best-practices).
   - **Regenerate** — plain button; swaps the card's content in place, never leaves the list (OTTO regenerates meta tags "on the spot, right inside the dashboard" — https://diyai.io/ai-tools/seo/reviews/search-atlas-review/).
   - **Ignore** — plain button. Ignore teaches the queue: it suppresses the suggestion *type* and files the card under the Ignored tab with restore (Semrush hide/restore; Ahrefs "Turn off for this project" — sources above). Menu option inside: "stop suggesting this kind of thing" (seoClarity disable-insight-type — https://www.seoclarity.net/technology/actionable-insights/). Ignored items may resurface if the underlying metric worsens (Linear snooze-until-activity semantics — https://linear.app/docs/triage).
   - **Delete** — in an overflow "..." menu; destructive + rare stays out of primary hierarchy (Polaris, source above). Delete removes one card; the UI copy states the ignore/delete distinction explicitly.
   - Exception to Polaris hover-hiding elsewhere: the four verbs are always-visible buttons, never behind hover — Google Ads' hover-X dismiss is the documented antipattern (https://support.google.com/google-ads/answer/10169817?hl=en) and a Search Atlas reviewer dinged controls "tucked in the upper right corner" (https://www.digitalinformationworld.com/2025/11/search-atlas-review-i-tested-ai-seo.html).

**Post-action feedback:**
- On any verb: card animates out, next card highlights, counter decrements (Linear triage auto-advance — https://linear.app/docs/triage; Superhuman one-decision flow — https://blog.superhuman.com/email-triage/).
- Handled cards collapse to a one-line receipt row ("Approved — new title went live Aug 20") rather than vanishing — progress is spatial and leaves a trust trail (GitHub PR "Viewed" collapse + progress bar — https://docs.github.com/pull-requests/collaborating-with-pull-requests/reviewing-changes-in-pull-requests).
- After approval, show a fix-verification status: Checking / Looking good / Fixed (GSC "Validate Fix" loop — https://support.google.com/webmasters/answer/7440203?hl=en).
- Everything approved is revertible, and one visible master "pause all changes" switch exists (OTTO's master render toggle + rollback-anytime — https://help.searchatlas.com/en/articles/11880172-otto-setup-functionality-and-deployment). The visible off-switch is what makes Approve feel safe.
- Standing copy at the top of every queue: "Nothing changes on your site until you approve it" (OTTO approval mode — https://searchatlas.com/otto-seo/).
- Bulk verbs scoped by suggestion type only ("approve all 4 title fixes"), never a global apply-all — blind bulk-approve produced documented ranking declines at Search Atlas (https://themarketingagency.ca/blog/search-atlas/).

## 3. Chat composer

- **Where:** one button, same fixed spot in the chrome on all pages, opening a right-side panel (HubSpot Breeze's single global entry point — https://knowledge.hubspot.com/ai/use-breeze-assistant; Intercom Fin Copilot's docked side panel — https://www.intercom.com/help/en/articles/8587194-how-to-use-copilot). Note: the owner's "chat composer almost throughout" impression of Search Atlas could not be verified against public docs — marketing describes a global conversational interface (https://searchatlas.com/atlas-agent/) but not per-page placement; the owner's first-hand observation stands.
- **Context inherited automatically:** current category, connected property, selected date range, and any card it was opened from. Never asks "which site?" — one operator, one business (Notion Agent inherits current-page context by default — https://www.notion.com/help/notion-agent). Metric tiles and cards get an "ask about this" affordance that opens the panel with that item attached (Intercom highlight-to-ask — source above).
- **Never a blank box:** opens with 3-4 tappable page-scoped starter prompts ("Why did clicks drop this week?", "Explain this number") — NN/g finds users can't tell what a bare "How can I help?" bot is for (https://www.nngroup.com/articles/site-ai-chatbot/ ; https://www.nngroup.com/articles/prompt-controls-genai/). Every response carries quick-action chips including a standing **"Explain simpler"** — the owner's own recurring request, as a one-tap control.
- **What it may trigger — the single most important rule:** chat proposes, the queue disposes. Any chat request that would change the site materializes as a suggestion card in that category's queue with the same four verbs — never as prose that dies in the transcript. This is exactly how Search Atlas separates channels: the agent prepares deployable outputs, "a human has to approve them in the dashboard" (https://searchatlas.com/atlas-agent/ ; https://www.eesel.ai/blog/search-atlas-ai-seo-software-en-2). Read-only questions answer inline with cited data.
- **Secondary role — navigation:** chat can jump to any pre-filtered view ("show me pages losing clicks"), like reviewers using Atlas Brain "like Spotlight" (https://behindrankings.com/search-atlas-review/) — but every chat-reachable action must also exist as a visible button; chat is an accelerator, never the sole path (https://uxdesign.cc/why-conversational-interfaces-are-taking-us-back-to-the-dark-ages-of-usability-fa45fefb446b).

## 4. Global flow

**Session start — Home:**
- One card per category: headline number + green/red delta + "N suggestions waiting" badge; every number and badge is a link into the category (Ahrefs Dashboard cards, "clicking metrics takes users directly to corresponding reports" — https://ahrefs.com/academy/how-to-use-ahrefs/dashboard/overview). The dashboard doubles as the nav — this is the "flow" the owner named.
- Above the cards, a 2-3 item insight strip: auto-generated plain-word alerts ("Your quote page lost half its Google clicks — see why"), each deep-linking into the relevant queue. The AI speaks first; the owner never has to notice the problem or compose a question (Semrush Copilot feed — https://www.mavlers.com/blog/semrush-copilot-guide/, Semrush's own KB page since repurposed so exact card layout is third-party-sourced; Vercel Agent's pre-computed investigations — https://vercel.com/docs/agent/investigation). Sharp metric drops get the "likely cause" attached automatically.
- Setup card with completion bar and green checks per connection (GSC, GA4, site) — OTTO V3's landing pattern (https://help.searchatlas.com/en/articles/11833701-introducing-otto-v3-smarter-faster-and-built-for-scale). Setup itself is a strictly ordered checklist with achievement ticks, not a settings page (Wix — https://support.wix.com/en/article/wix-seo-setup-checklist-creating-your-seo-checklist). After connections, every category self-populates its queue — first session ends with ready suggestions, not configuration (OTTO pixel-then-populate — https://help.searchatlas.com/en/articles/11844304-how-do-i-install-the-otto-pixel-on-my-website).

**Always knowing the next action:**
- No dead-end screens: every metric and issue carries "Fix this" (opens/creates its card) or at minimum "Why this matters" (Search Atlas Site Auditor: "each issue gets clear next steps" — https://searchatlas.com/site-auditor/).
- Within a category, a "go through them" mode: one card at a time, big verbs, auto-advance, running count "3 left" (Superhuman triage flow — https://help.superhuman.com/hc/en-us/articles/45295217605523-Achieve-Inbox-Zero).
- On the Site Pages category, every page gets one red/yellow/green dot from its open suggestions; the list sorted red-first *is* the queue (Yoast traffic lights — https://yoast.com/help/guide-for-yoast-seo-for-shopify/).

**Progress and momentum:**
- Sticky per-category progress: "You've handled 4 of 6 this week" — the meter moves on approve AND on ignore/delete, so reviewing counts as work and the owner is never punished for saying no (Google Ads: dismissing also raises the optimization score — https://support.google.com/google-ads/answer/9061546?hl=en). Critically, this meter measures suggestions-handled, never real-outcome theater (see antipattern 6).
- Running outcome counters per category ("14 fixes live, 3 pages improved") — OTTO Grade's "issues fixed / time saved" counters reassure that approving did something (https://help.searchatlas.com/en/articles/11833701-introducing-otto-v3-smarter-faster-and-built-for-scale).
- Queue-zero is celebrated with the cleared date (Superhuman Inbox Zero — https://blog.superhuman.com/how-to-split-your-inbox-in-superhuman/).
- Trust dial over time: start everything in approval mode; later, per-type auto-approve for suggestion kinds the owner has approved repeatedly (Linear per-property auto-apply — https://linear.app/changelog/2025-09-19-auto-apply-triage-suggestions; OTTO's named approval mode — https://searchatlas.com/otto-seo/).
- All UI copy at 6th-8th grade reading level, lintable in CI (https://digital.gov/guides/plain-language/principles); severity written as consequence — "Google can't see this page," not "noindex detected" (Wix — https://support.wix.com/en/article/optimizing-your-site-with-the-wix-seo-assistant).

## 5. Top 8 antipatterns to avoid

1. **Tool sprawl under abstract labels.** Search Atlas: ~10 toolkits, reviewer "needed 3 days to just get familiar" (https://www.demandsage.com/search-atlas-review/); Semrush admitted its old 50+-tool nav "was a bit confusing" and rebuilt it (https://www.semrush.com/news/260365-new-semrush-navigation/). AOOS's 30 pages is this exact failure; the 6-8 cap must be enforced permanently — new features go inside a category, never as new nav.
2. **Unranked, uncapped suggestion floods.** "OTTO doesn't prioritize issues by severity, leaving users overwhelmed" (https://behindrankings.com/search-atlas-review/); "3.5 hours weekly reviewing" (https://themarketingagency.ca/blog/search-atlas/); seoClarity's 120+ insights are enterprise-scale burial for a solo operator (https://www.seoclarity.net/technology/actionable-insights/). Cap the visible queue; don't just filter it.
3. **Blind bulk-approve.** Search Atlas users who bulk-approved "report ranking declines"; generic AI rewrites "strip away the unique value propositions" (https://themarketingagency.ca/blog/search-atlas/). Batch verbs scoped to safe mechanical types only; no global apply-all.
4. **Actions hidden behind hover and kebab menus.** Google Ads' hover-X dismiss and 3-dot "Dismiss all" (https://support.google.com/google-ads/answer/10169817?hl=en); Search Atlas controls "tucked in the upper right corner... took me a while to locate" (https://www.digitalinformationworld.com/2025/11/search-atlas-review-i-tested-ai-seo.html). All four verbs permanently visible, same order everywhere. (Sole exception: Delete, deliberately demoted per Polaris.)
5. **Dismissal without memory.** GSC recommendations expire with no documented dismiss control, so users can't tell "I handled this" from "it went away" (https://support.google.com/webmasters/answer/15107108?hl=en). Every action gets a receipt in the Done tab; every ignore is restorable.
6. **Score theater.** Squarespace's SEO score reads 100% on a badly optimized site because it counts filled fields (https://sarahmoon.net/blog/squarespace-seo-completion-panel); Google Ads' score is criticized for nudging spend and punishing inaction (https://www.storegrowers.com/google-ads-optimization-score/ ; https://dagmarmarketing.com/blog/truth-google-ads-recommendations/). Any AOOS score ties to real data movement or suggestions-handled — never field-presence, and never a real outcome metric that drops when the owner ignores a suggestion.
7. **Jargon in labels and metrics.** Search Atlas "assumes existing SEO knowledge," "probably not for a complete beginner who has never heard of a meta description" (websites2know.com via review corpus); "some of these metrics take time to understand" (https://www.digitalinformationworld.com/2025/11/search-atlas-review-i-tested-ai-seo.html). Every label passes the "plain words to a moving-company owner" test; explanations live next to the number, not in a help center (Wave's documented gap — https://support.waveapps.com/hc/en-us/articles/360041575251-View-and-understand-your-profit-loss-statement).
8. **Chat as substitute for navigation, or chat output dying in the transcript.** Search Atlas users route around the failed nav via the Atlas Brain search bar (https://behindrankings.com/search-atlas-review/ ; https://websites2know.com/searchatlas-review/) — if users need a command palette to survive your nav, the nav failed. And a bare prompt box with no scoped starters leaves users unable to tell what it's for (https://www.nngroup.com/articles/site-ai-chatbot/). Every chat capability also exists as a visible control; every chat-initiated change lands as a queue card.

**Verification caveats carried forward from research:** Surfer Grow Flow's own docs 404 (feature likely retired — pattern kept on third-party sourcing only); Semrush Copilot's KB page was repurposed (card-level detail is third-party); Search Atlas chat placement per-screen is unverified from public docs (owner's first-hand observation stands); Conductor's card-level dismiss/snooze verbs are not publicly documented.
